PavingOS Engineering Specs

Engineering Specification — PavingOS

Version: MVP v1 (Authoritative)

Focus: Field reliability (offline), financial correctness, scalable estimating logic

1. Product & Architectural Goals

Primary Product Goals

Opinionated estimating built for paving (templates → assemblies → estimates).

Zero-reentry workflow: Estimate → Job → Actuals → Invoice.

Continuous feedback loop from job actuals back to estimating insights.

Foreman-first execution experience with minimal friction.

Day-1 Non-Negotiables

Minimum viable offline support for foremen:

View assigned jobs

Start / complete job

Log labor hours

Add notes

Capture photos

Sync later without data loss

Financial correctness

No floating-point currency math

Deterministic, auditable calculations

Multi-tenant, secure-by-default

Row Level Security everywhere

Strong auditability for financial actions

3. Offline Strategy (Authoritative)

Philosophy

This is not a full local-first replica.

This is minimum viable offline, optimized for reliability and speed.

Client Behavior

Foreman actions are written first to IndexedDB.

Each action generates a job_event with a UUID client_event_id.

Photos are staged locally until upload succeeds.

Sync runs automatically when connectivity is detected.

Server Behavior

Events are appended idempotently.

Duplicate client_event_ids are ignored.

Derived summaries are recomputed server-side.

Why This Approach

Predictable

Auditable

Easy to reason about

Avoids premature sync-engine complexity

4. Authentication & Foreman PIN Security

Supabase Auth

Email magic link for all users.

Sessions managed server-side (@supabase/ssr).

Foreman PIN Gate (Required)

Field devices are shared. We add a local PIN lock.

Behavior

After initial login, foreman sets a 4–6 digit PIN.

App requires PIN to unlock cached jobs and offline UI.

PIN is required after:

App restart

Inactivity timeout

Ops/Owner can remotely reset or lock PINs.

Data Model

profiles

user_id (pk)

pin_hash text

pin_set_at timestamptz

pin_failed_attempts int

pin_locked_until timestamptz

Notes

PIN ≠ Auth token

PIN protects against casual misuse, not device compromise

IndexedDB encryption may be added later
